# Commercial and research ML upscaling / frame generation: working notes

Compiled 2026-09-14 from primary sources where possible. "(secondary)" = only press/third-party
source was reachable; "UNVERIFIED" = could not confirm. Numbers are vendor claims unless stated.

---

## 1. NVIDIA DLSS

**DLSS 1 vs DLSS 2 (Super Resolution)**
- DLSS 1 had to be trained separately for each game. DLSS 2.0 (23 Mar 2020) "trains using non-game-specific content, delivering a generalized network that works across games." https://www.nvidia.com/en-us/geforce/news/nvidia-dlss-2-0-a-big-leap-in-ai-rendering/
- DLSS 2 is temporal. Its inputs are low-res aliased frames, engine motion vectors and the previous high-res output (temporal feedback), processed by a convolutional autoencoder. It is trained against 16K offline-rendered reference images and runs on RTX Tensor Cores. Modes are Quality/Balanced/Performance, up to 4x pixel upscaling. (same URL)
- The network does image reconstruction/accumulation, i.e. it replaces TAA-style history heuristics. NVIDIA has not published the exact output parameterisation (direct colour vs. blend weights): UNVERIFIED.

**DLSS 3 Frame Generation (20 Sep 2022)**
- Inputs: "current and prior game frames, an optical flow field generated by Ada's Optical Flow Accelerator, and game engine data such as motion vectors and depth." https://www.nvidia.com/en-us/geforce/news/dlss3-ai-powered-neural-graphics-innovations/
- Optical flow captures "particles, reflections, shadows, and lighting, which are not included in game engine motion vector calculations." (same URL)
- It runs as a GPU post-process, so it raises frame rate even when the CPU is the bottleneck. DLSS 3 is SR + FG + Reflex. Requires RTX 40 (Ada: 4th-gen Tensor Cores + Optical Flow Accelerator). (same URL)

**DLSS 3.5 Ray Reconstruction (22 Aug 2023)**
- Replaces "hand-tuned denoisers with an NVIDIA supercomputer-trained AI network", trained with "5X more data than DLSS 3". Works on all RTX GPUs. https://www.nvidia.com/en-us/geforce/news/nvidia-dlss-3-5-ray-reconstruction/

**DLSS 4 (CES, 6 Jan 2025)**
- SR and RR moved from CNN to a vision transformer with "double the parameters of the CNN model". Self-attention works "across the entire frame, and over multiple frames". Available on all RTX GPUs. https://www.nvidia.com/en-us/geforce/news/dlss4-multi-frame-generation-ai-innovations/
- A "4x compute" figure for the transformer appears only in secondary/search snippets (secondary).
- Multi Frame Generation gives "up to three additional frames per traditionally rendered frame" and is RTX 50 only. (same URL)
- The new FG model is "40% faster", "uses 30% less VRAM", and runs "once per rendered frame to generate multiple frames". Hardware optical flow was replaced by an AI model. The upgraded FG model runs on RTX 50 and RTX 40. (same URL)
- Frame pacing: Blackwell "Hardware Flip Metering" moves "frame pacing logic to the display engine". (same URL)
- Streamline DLSS-G integration requires depth, dense motion vectors (camera + object motion), and the backbuffer via swap-chain proxy. A hudless buffer plus a UI alpha (or UI colour+alpha) buffer is "critical" for image quality. `numFramesToGenerate` sets the MFG count. Reflex via Streamline is mandatory. Needs Win10 20H1+ and HW-accelerated GPU scheduling. https://github.com/NVIDIAGameWorks/Streamline/blob/main/docs/ProgrammingGuideDLSS_G.md
- MFG inputs: "Depth buffers, Motion vectors, HUD-less color buffers, UI color buffers". https://developer.nvidia.com/blog/how-to-integrate-nvidia-dlss-4-into-your-game-with-nvidia-streamline

**DLSS 4.5 (CES, 6 Jan 2026; FG parts released 31 Mar 2026)**
- 2nd-gen transformer SR has "five times the compute power of the original transformer model". It "trains and infers directly in linear space". It uses FP8 on RTX 40/50. RTX 20/30 "lack native FP8 support, so Models M and L carry a heavier performance impact". https://www.nvidia.com/en-us/geforce/news/dlss-4-5-dynamic-multi-frame-gen-6x-2nd-gen-transformer-super-res/
- 6X MFG generates up to 5 frames per rendered frame. Dynamic MFG switches between 1X and 6X in real time to hit a target or refresh rate. RTX 50 only. Driver 595.97+. The enhanced FG model uses additional engine UI buffers for static UI. https://nvidia.com/en-us/geforce/news/dlss-4-5-dynamic-multi-frame-generation-6x-mode-released
- DLSS 4.5 Ray Reconstruction (Gamescom, 25 Aug 2026) is a 2nd-gen transformer with "35% more compute capability" and "20% more parameters". All RTX GPUs. Early Access in August, full release planned for September 2026. https://www.nvidia.com/en-us/geforce/news/gamescom-2026-dlss-4-5-ray-reconstruction-release-announcements-trailers/

**Reflex / latency**
- Reflex synchronises CPU and GPU (render-queue reduction). NVIDIA claims DLSS 3 + Reflex latency is up to 2x lower than native without Reflex. https://www.nvidia.com/en-us/geforce/news/dlss3-ai-powered-neural-graphics-innovations/
- Reflex 2 Frame Warp is covered in section 6.

## 2. AMD FSR

- **FSR 1** (spatial, single frame, no ML): EASU ("detects and recreates high-resolution edges", Lanczos-like, 12 taps) followed by RCAS sharpening. Placed after AA and tonemapping. https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-spatial/
- **FSR 2** (temporal, analytic, "does not require ML"): inputs are colour, depth, motion vectors, exposure, reactive/transparency masks and jitter. Stages: luminance pyramid, reconstruct & dilate, depth clip, locks, reproject & Lanczos accumulate, RCAS. Uses HLSL CS_6_2/6_6. https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-temporal/
- **FSR 3 / 3.1** (analytic FG, vendor-agnostic): "temporal upscaling, along with a new optical flow implementation to reproject samples from 2 rendered frames". 3.1 decouples FG from the upscaler, so FG can pair with other upscalers. A proxy swapchain (DX12 and Vulkan) handles FG/UI dispatch and "modulating frame pacing". UI options: render UI in a per-presented-frame callback, a separate UI texture, or a HUD-less texture for automatic UI detection. https://gpuopen.com/manuals/fidelityfx_sdk/techniques/super-resolution-interpolation/
- FSR 3 optical flow is classical. It is "based on AMD Fluid Motion Frames", works on 8x8 non-overlapping blocks (one vector per block), and uses a 6-level luminance pyramid with 7 iterations of SAD search (24x24 window, `msad4`), 3x3 median filter and upscale. It includes histogram-based scene-change detection, tracks up to 512 px, and uses about 26–28 MB at 4K. SM 6.2. https://gpuopen.com/manuals/fidelityfx_sdk/techniques/optical-flow/
- FSR 3 frame interpolation stages: interpolated-frame depth estimate, game-MV field, MV inpainting pyramid, optical-flow field, disocclusion mask, interpolation, inpainting pyramid, final inpaint. HLSL or Vulkan GLSL. https://gpuopen.com/manuals/fidelityfx_sdk/techniques/frame-interpolation/
- FG guidance: interpolate from at least 60 fps base; "Sub-30fps pre-interpolation should be absolutely avoided". Pair with Radeon Anti-Lag 2. https://gpuopen.com/amd-fsr-framegeneration/
- **FSR 4** (ML upscaler, announced 28 Feb 2025 with RX 9070): "trained using high-quality ground truth game data on AMD Instinct Accelerators and uses the hardware-accelerated FP8 Wave Matrix Multiply Accumulate (WMMA) feature of the AMD RDNA 4 architecture". Exclusive to RX 9000 at launch. https://newsroom.amd.com/news/amd-unveils-next-generation-amd-rdna-4-architectu/
- FSR 4 SDK (v4.0.2): DX12, Windows 10/11, RX 9000+. No reactive/transparency mask needed for particles. https://gpuopen.com/learn/amd-fsr4-gpuopen-release/
- **FSR "Redstone"** (released 10 Dec 2025, FSR SDK, Adrenalin 25.12.1). ML suite for RDNA 4:
  - FSR Upscaling (formerly FSR 4).
  - FSR Frame Generation: ML "predicts per-pixel motion and appearance" from previous and current frames, depth and MVs, using "optical flow estimation plus the motion vectors". Analytic fallback on other GPUs.
  - FSR Ray Regeneration: ML denoiser.
  - FSR Radiance Caching: ML "predicts light propagation ... based on sparse path-traced samples". Technical preview; production release planned for 2026.
  - Source: https://gpuopen.com/learn/amd-fsr-redstone-developers-neural-rendering/
- ML FG blends its predicted motion/appearance "with motion vector reprojection". It requires RX 9000 and Windows 11. The analytic fallback needs SM 6.2, DX12 and Windows 10/11. https://gpuopen.com/amd-fsr-framegeneration/
- **Older GPUs:** FSR SDK 2.3 (blog dated 24 Jun 2026) ships FSR Upscaling 4.1.1 for RX 7000 (RDNA 3) discrete GPUs, "closely matches" RX 9000 quality. FG 4.0.1, Ray Regeneration 1.2.0 and Radiance Caching 0.9.0 (still a preview) remain RDNA 4 only. https://gpuopen.com/learn/amd-fsr-sdk-2-3-blog/
- Adrenalin 26.6.2 (22 Jun 2026) enabled FSR 4.1 on RX 7000 in 300+ games using an INT8 model. Only upscaling was backported. RDNA 2 (RX 6000) support was reportedly planned for early 2027 (secondary). https://www.neowin.net/news/amd-2662-driver-brings-fsr-41-support-to-rdna-3-rx-7000-series-graphics-cards/ and https://www.tomshardware.com/pc-components/gpu-drivers/amd-brings-official-fsr-4-1-support-to-rx-7000-series-gpus-int8-model-now-available-in-300-games-rdna-3-apus-also-getting-fsr-4-1-soon
- No statement found about Polaris (RX 400/500, i.e. the thesis RX 580). Only analytic FSR 1/2/3 apply there.

## 3. Intel XeSS

- XeSS-SR has two paths. One is Intel-optimised (XMX on Arc, also Iris Xe). The other is a cross-vendor path on "any GPU supporting Shader Model 6.4 or above", with "DP4A" acceleration recommended. https://www.intel.com/content/www/us/en/developer/topic-technology/gamedev/xess.html
- The DP4a path uses a different, lighter network with lower quality/throughput than XMX (secondary). https://www.tomshardware.com/news/intel-xess-technology-demo-and-overview
- **XeSS 2** (announced Dec 2024 with Arc B-series; whitepaper 17 Mar 2025). XeSS-FG has three stages: (1) motion-vector reprojection from engine MVs; (2) an "AI model trained for optical flow reprojection" that captures shadows, reflections and particles; (3) "a second AI model with a blend function" that picks among both candidate sets. Inputs are MVs and depth. UI is either repeated or re-rendered for the generated frame. The whitepaper said FG needs "Intel Arc GPUs with XMX hardware acceleration". XeLL cuts latency by "up to 45%". Claimed scaling is up to 3.9x vs native (F1 24). https://www.intel.com/content/www/us/en/developer/articles/technical/xess2-whitepaper.html
- XeLL integration is a prerequisite for XeSS-FG. APIs: DX12 and Vulkan (DX11 is SR only). https://www.intel.com/content/www/us/en/developer/topic-technology/gamedev/xess.html
- **XeSS 3**: Multi Frame Generation with up to 3 generated frames (2x/3x/4x). It is "only available on Intel devices" and can be force-enabled in any XeSS 2 FG title through the driver. Targets Arc A/B discrete and Core Ultra Series 2/3 iGPUs. (same URL)
- Driver rollout was Jan–Feb 2026 (e.g. 32.0.101.8509) (secondary). https://wccftech.com/intel-officially-rolls-out-xess-3-multi-frame-generation-for-arc-alchemist-and-battlemage-gpus/
- Inconsistency: the SDK README says XeSS-FG is available on "non-Intel GPUs with SM 6.4 support" and XeLL on non-Intel GPUs when combined with FG. That contradicts the whitepaper's XMX-only statement, so cross-vendor FG must have been added later. https://github.com/intel/xess

## 4. Apple, Sony, mobile

- **Apple MetalFX**: spatial and temporal scalers since iOS 16 / macOS 13 (2022). The temporal upscaler is ML-based ("part of Apple platforms since 2022"). WWDC25 added a denoised upscaler that combines RT denoising and upscaling from normals, albedo, roughness and specular inputs, and a frame interpolator. https://developer.apple.com/videos/play/wwdc2025/211/
- The frame interpolator (`MTLFXFrameInterpolator`, iOS/macOS 26) takes "two rendered frames, motion vectors and depth". UI modes: composited (frame N with and without UI), offscreen UI texture, or app-drawn UI on every frame. https://developer.apple.com/documentation/metalfx/mtlfxframeinterpolatordescriptor
- Whether the interpolator itself is ML-based: UNVERIFIED.
- **Sony PSSR** (PS5 Pro, Nov 2024): an ML upscaler on dedicated ML hardware quoted at 300 TOPS (8-bit) / 67 TFLOPS (16-bit) from Cerny's Dec 2024 technical seminar (secondary). https://www.back2gaming.com/guides/mark-cerny-hosts-technical-seminar-on-ps5-pro-hardware/
- **Upgraded PSSR** (27 Feb 2026, debut in Resident Evil Requiem): "a very different approach to not only the neural network but also the overall algorithm". It comes from the Project Amethyst co-development with AMD, i.e. it is FSR 4-derived. https://blog.playstation.com/2026/02/27/upgraded-pssr-upscaler-is-coming-to-ps5-pro/
- Cerny to Digital Foundry (Mar 2026): "FSR Upscaling uses 8-bit floating point, and PSSR uses 8-bit integer ... the same model is used, but it's trained on different data" (secondary quote). https://www.notebookcheck.net/PlayStation-5-s-PSSR-2-0-uses-AMD-s-FSR-4-s-INT8-version-that-may-skip-PC-RDNA-2-3-GPUs.1258631.0.html
- Cerny also said ML frame generation will come to "PlayStation platforms" but not in 2026 (secondary). https://www.kitguru.net/gaming/joao-silva/mark-cerny-confirms-ml-based-frame-generation-is-coming-to-playstation/
- **Arm ASR** (10 Jul 2024): temporal and analytic, derived from FSR 2, MIT licence, for mobile GPUs. https://developer.arm.com/community/arm-community-blogs/b/mobile-graphics-and-gaming-blog/posts/introducing-arm-accuracy-super-resolution
- **Arm Neural Super Sampling (NSS)** (announced 12 Aug 2025; Arm GPUs in 2026). A 4-level UNet predicts per-pixel 4x4 filter kernels, temporal accumulation/rectification coefficients and a hidden state. A classical accumulator then applies these. Inputs are colour, MVs, depth, jitter and camera matrices. Runs through Vulkan ML extensions. This is the closest commercial analogue to "small net predicts blend parameters". https://developer.arm.com/community/arm-community-blogs/b/mobile-graphics-and-gaming-blog/posts/how-arm-neural-super-sampling-works
- **Qualcomm Snapdragon GSR**: SGSR 1 is a single-pass spatial upscaler (12-tap Lanczos-like + sharpening). SGSR 2 is temporal for Adreno. BSD-3 licence, no ML. https://github.com/SnapdragonGameStudios/snapdragon-gsr
- Qualcomm "Adreno Neural Fusion" (Sept 2026: Matrix Cores in the GPU for ML SR + FG) (secondary, not verified at primary source).

## 5. Research video frame interpolation (VFI)

- **RIFE** (Huang et al., ECCV 2022; arXiv 2011.06294). IFNet is coarse-to-fine: 3 IFBlocks at scales 4/2/1 directly regress intermediate flows F(t->0), F(t->1) plus a fusion mask, with no cost volume. Trained with privileged distillation. Supports arbitrary timestep. 9.8 M parameters, 16 ms at 640x480 on TITAN X (Pascal). DAIN is 24.0 M / 436 ms; SuperSlomo 19.8 M / 62 ms. https://arxiv.org/abs/2011.06294 (tables via https://ar5iv.labs.arxiv.org/html/2011.06294)
- The RIFE README claims "30+FPS for 2X 720p interpolation on a 2080Ti". https://github.com/hzwer/ECCV2022-RIFE
- **FILM** (Reda et al., Google Research, ECCV 2022). A shared-weight, scale-agnostic feature pyramid feeds bidirectional flow estimation per level, then warping and a UNet-like fusion decoder. Trained from frame triplets only, with no pre-trained flow/depth nets, using a Gram-matrix loss. Targets large motion. 0.393 s per 720p frame on a V100, 4.48 GB peak memory. https://arxiv.org/abs/2202.04901 (numbers via https://ar5iv.labs.arxiv.org/html/2202.04901)
- **IFRNet** (Kong et al., CVPR 2022). A single encoder-decoder jointly refines bilateral intermediate flow and an intermediate feature. Uses task-oriented flow distillation and a geometry-consistency loss. https://arxiv.org/abs/2205.14620 — parameter counts UNVERIFIED (PDF not retrievable).
- **EMA-VFI** (Zhang et al., CVPR 2023). Inter-frame attention extracts motion and appearance jointly in a hybrid CNN+Transformer. At 512x512 on a 2080 Ti: 132 ms / 2.01 GB (full), 25 ms / 1.42 GB (small). https://arxiv.org/abs/2303.00440 (runtime from https://arxiv.org/html/2303.00440, Table 7)
- **Why these are not directly usable in games** (synthesis from the facts above):
  - Cost: tens to hundreds of ms per frame on high-end GPUs, while a 60->120 fps budget is about 8 ms total.
  - Inputs: RGB only. They must estimate all motion from pixels and ignore engine MVs, depth and UI separation, whereas every commercial FG consumes MVs + depth and a HUD-less/UI buffer.
  - Accuracy: they are trained on natural video, not on aliased, jittered renders with HUDs.
  - Latency: interpolation still delays the real frame, and nothing is integrated with pacing or Reflex-style latency reduction.

## 6. Cross-cutting

- **Accelerators and precision.**
  - NVIDIA Tensor Cores: DLSS 4.5 relies on FP8 on RTX 40/50, and RTX 20/30 pay a penalty without it (section 1 URL).
  - AMD: FSR 4 uses FP8 WMMA on RDNA 4. RDNA 4 claims "up to 8x INT8 throughput per AI accelerator (for sparse matrices)" vs the previous generation. The RDNA 3 port uses an INT8 model. https://newsroom.amd.com/news/amd-unveils-next-generation-amd-rdna-4-architectu/
  - Intel: XMX (INT8 matrix engines) vs DP4a (a dot-product shader intrinsic), with a lighter model on DP4a (section 3).
  - Sony: PS5 Pro ML hardware at 300 8-bit TOPS, running an INT8 model (section 4).
  - Arm: NPU / GPU neural accelerators through Vulkan ML extensions.
  - Common pattern: inference runs as dense matrix multiplies/convolutions in 8-bit formats. Without dedicated INT8/FP8 support the same model costs much more (FSR 4 had to be requantised to INT8 for RDNA 3).
- **Disclosed network sizes.**
  - Almost none in absolute terms. NVIDIA gives only relative figures: transformer = 2x CNN parameters; 4.5 SR = 5x compute of the 1st-gen transformer; 4.5 RR = +20% parameters, +35% compute.
  - AMD, Intel, Sony and Apple disclose no parameter counts.
  - Arm NSS discloses architecture (4-level UNet) but not size.
- **UI/HUD in FG.** All vendors separate UI from the scene:
  - DLSS-G: hudless + UI alpha/colour buffers, with DLSS 4.5 adding more engine UI data.
  - FSR 3: UI callback, UI texture or HUD-less auto-detection.
  - XeSS-FG: repeat UI or re-render it for the generated frame.
  - MetalFX: composited, offscreen or every-frame UI.
- **Interpolation vs extrapolation.**
  - All shipping FG (DLSS 3/4/4.5, FSR 3/Redstone, XeSS-FG/MFG, MetalFX) interpolates between two rendered frames. It therefore holds back the newest real frame, which is why each is paired with Reflex / Anti-Lag 2 / XeLL and why AMD asks for a base of at least 60 fps.
  - **NVIDIA Reflex 2 Frame Warp** (announced 6 Jan 2025) is late reprojection, a form of extrapolation. The CPU computes the next camera pose from the latest input and the just-rendered frame is warped to it "just before the rendered frame is sent to the display". Disocclusion holes are filled by a "latency-optimized predictive rendering algorithm that uses camera, color and depth data from prior frames". NVIDIA claims up to 75% latency reduction (THE FINALS 4K: 56 ms to 14 ms). RTX 50 first. https://www.nvidia.com/en-us/geforce/news/reflex-2-even-lower-latency-gameplay-with-frame-warp/
  - Frame Warp was still unreleased with no shipping game or driver toggle as of late July 2026 (secondary). https://hwbusters.com/news/nvidia-reflex-2-is-18-months-old-and-still-hasnt-shipped/
  - Research extrapolation: ExtraNet (ACM TOG / SIGGRAPH Asia 2021) uses G-buffers of the extrapolated frame, MVs and a network for shading inpainting. https://dl.acm.org/doi/10.1145/3478513.3480531
  - Intel ExtraSS (SIGGRAPH Asia 2023) combines G-buffer-guided warping, a shading-refinement network, and joint spatial SR + extrapolation. https://dl.acm.org/doi/fullHtml/10.1145/3610548.3618224
  - GFFE (ACM TOG 2024) is G-buffer-free extrapolation. https://dl.acm.org/doi/10.1145/3687923

## Not verified (treat with care)

- Exact output of DLSS 2/4 networks (direct pixels vs kernels/blend weights). The DLSS 4 transformer "4x compute" figure (only 2x parameters is on the NVIDIA page).
- Whether Reflex 2's inpainting is a neural network. Its release status after July 2026 (primary pages were blocked).
- Whether DLSS 4.5's enhanced FG model (UI buffers) also applies to RTX 40.
- FSR 4 on RDNA 2 in "early 2027" and RDNA 3 APU timing (secondary only). No AMD statement for Polaris/RX 580.
- Parameter counts for IFRNet, EMA-VFI and FILM (FILM's paper gives none). Any absolute size for DLSS, FSR 4, XeSS, PSSR or NSS networks.
- Whether the MetalFX frame interpolator is ML-based.
- PS5 Pro 300 TOPS / 67 TFLOPS: from secondary coverage of Cerny's seminar, not the video itself. PSSR 2 INT8 quote: secondary report of a Digital Foundry interview.
- XeSS-FG on non-Intel GPUs: SDK README vs whitepaper conflict. Exact XeSS 3 driver dates are secondary.
- Qualcomm Adreno Neural Fusion (Sept 2026): press-only. SGSR 1/2 release years.
